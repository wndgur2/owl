# Owl BLE 프로토콜 v1 (초안)

펌웨어(`firmware/`)와 앱(`android/`), PC 도구(`tools/`)가 공유하는 **계약서**예요.
이 문서를 바꾸면 세 곳을 같은 커밋에서 같이 고쳐야 해요.
레퍼런스 구현은 `tools/owlproto.py`이고, `tools/tests/`의 테스트가 이 문서의 숫자를 검증해요.

- 모든 정수는 **little-endian**
- `u8/u16/u32/u64` 부호 없음, `i16` 부호 있음
- 문자열 없음 (펌웨어 파싱을 단순하게 유지)

## 1. 설계 원칙

1. **기기는 녹음만, 판단은 폰이.** 기기는 오디오를 세그먼트 단위로 플래시에 쌓아두고, 폰이 연결되면 꺼내 가요.
2. **폰이 ACK하기 전엔 지우지 않는다.** 전송 중 끊겨도 데이터가 사라지지 않아요.
3. **기기 시계를 믿지 않는다.** 기기는 `(boot_count, uptime_ms)`만 기록하고, 실제 시각 변환은 폰이 해요(4장).
4. **풀(pull) 방식.** 기기가 먼저 데이터를 밀어내지 않아요. 폰이 목록을 묻고, 원하는 세그먼트를 요청해요. 재전송·이어받기가 쉬워져요.

## 2. GATT 서비스

Base UUID: `a269xxxx-8c8b-40f7-a91b-3ffa7ab560b9`

| 이름 | UUID (xxxx) | 속성 | 방향 | 용도 |
|---|---|---|---|---|
| Owl Service | `0001` | - | - | 서비스 |
| STATUS | `0002` | Read, Notify | 기기 → 폰 | 배터리, 저장 공간, 미전송 개수 |
| CONTROL | `0003` | Write, Notify | 양방향 | 명령(폰→기기)과 응답(기기→폰) |
| DATA | `0004` | Notify | 기기 → 폰 | 세그먼트 바이트 스트림 |

광고 이름: `Owl-XXXX` (XXXX = 기기 주소 하위 2바이트 hex). 광고에 서비스 UUID 포함.

광고 간격: 평소 1초 (평균 약 0.01–0.02mA 추정, M5에서 측정). 기기는 켜져 있는 동안 늘 광고해서 폰이 언제든 연결할 수 있게 해요.

연결 파라미터 목표: MTU 247, 2M PHY, Data Length Extension(251), 연결 간격 15–30ms (전송 중) / 연결 해제 (평소).
Android 기준 실효 처리량은 대략 수십 KB/s로 잡아요 (측정 후 갱신).

### 2.1 STATUS (24바이트)

| 오프셋 | 타입 | 필드 | 설명 |
|---|---|---|---|
| 0 | u8 | proto_ver | `1` |
| 1 | u8×3 | fw_ver | major, minor, patch |
| 4 | u16 | battery_mv | 배터리 전압 (mV) |
| 6 | u8 | flags | bit0 충전 중(보류, 아래 참고), bit1 녹음 켜짐, bit2 저장 공간 부족(≥90%), bit3 저장 공간 가득 참 |
| 7 | u8 | reserved | `0` |
| 8 | u32 | storage_used_kb | |
| 12 | u32 | storage_total_kb | |
| 16 | u16 | pending_segments | 아직 ACK 안 된 세그먼트 수 |
| 18 | u16 | reserved | `0` |
| 20 | u32 | boot_count | 4장 참고 |

- bit1 녹음 켜짐: 사용자가 녹음을 끄지 않은 상태(버튼 2초 또는 SET_RECORDING). 저장 공간이 가득 차서 멈춘 경우에도 1이고, 그건 bit3으로 알아요.
- bit0 충전 중: 보드에 충전 상태를 읽을 핀이 없어서(회로도 V1.2) 지금은 항상 `0`. 쓸지는 [PRD 10장](../docs/prd.md#10-미결정-사항) H.
- 기기가 꺼져 있으면(버튼 5초, 배터리 부족) 광고도 꺼져서 STATUS를 읽을 수 없어요. 폰은 "연결 끊김"으로만 알아요.

배터리 잔량(%)은 폰이 전압 곡선으로 계산해요. 기기에 곡선을 넣으면 배터리를 바꿀 때마다 펌웨어를 고쳐야 해서요.

### 2.2 CONTROL

요청(폰 → 기기, Write With Response):

```
[op u8][seq u8][payload ...]
```

응답(기기 → 폰, Notify):

```
[op | 0x80][seq u8][result u8][payload ...]
```

`seq`는 폰이 매기는 0–255 순환 번호. 응답은 같은 `seq`를 돌려줘요.

TIME_SYNC의 `tz_offset_min`은 기기가 쓰지 않아요(시각 변환은 폰이 해요, 4장). 자리만 잡아둔 필드예요.

| op | 이름 | 요청 payload | 응답 payload |
|---|---|---|---|
| `0x01` | TIME_SYNC | `unix_ms u64`, `tz_offset_min i16` | `boot_count u32`, `uptime_ms u64` |
| `0x02` | LIST_SEGMENTS | `after_id u32`, `max u8` | `count u8`, 그 뒤 `count`개의 `{id u32, type u8, size u32}` (9바이트씩) |
| `0x03` | FETCH_SEGMENT | `id u32`, `offset u32` | 없음 (데이터는 DATA로 옴) |
| `0x04` | ACK_SEGMENT | `id u32`, `crc32 u32` | 없음. CRC가 맞으면 기기는 해당 세그먼트를 지울 수 있음 |
| `0x05` | ABORT | 없음 | 없음. 진행 중인 FETCH 중단 |
| `0x06` | SET_RECORDING | `on u8` (0 끄기, 1 켜기) | 없음. 녹음 켜짐 상태를 바꾸고 이벤트 2/3(arg 1 앱)을 남김 |
| `0x10` | SET_CONFIG | `key u8`, `value u32` | 없음 |

`result`: `0` OK, `1` 알 수 없는 op, `2` 잘못된 길이, `3` 세그먼트 없음, `4` CRC 불일치, `5` 바쁨.

LIST_SEGMENTS 응답 하나에 들어가는 최대 개수: (244 − 4) / 9 = **26개**. 더 있으면 마지막 id로 다시 요청해요.

SET_CONFIG 키 (초안):

| key | 의미 | 기본값 |
|---|---|---|
| `1` | Opus 비트레이트 (bps) | 16000 |
| `2` | VAD 민감도 (0–3) | 2 |
| `3` | 세그먼트 최대 길이 (초) | 300 |

### 2.3 DATA

```
[segment_id u32][offset u32][bytes ...]
```

헤더 8바이트. MTU 247이면 ATT payload 244바이트 → 청크당 **236바이트**.
`offset`은 세그먼트 처음부터의 바이트 위치. 폰은 offset이 비면(패킷 유실, 재연결) 그 위치부터 FETCH_SEGMENT를 다시 보내면 돼요.
세그먼트 전체를 받으면 폰이 CRC32를 계산해서 ACK_SEGMENT로 보내요.

## 3. 세그먼트 포맷

기기 플래시와 BLE 전송에서 **같은 바이트 그대로** 써요. 변환 코드가 없으면 버그도 없어요.
플래시에서는 세그먼트 하나가 LittleFS 파일 하나예요. ACK를 받으면 그 파일을 지워요(`decisions.md` #18).

### 3.1 헤더 (32바이트)

| 오프셋 | 타입 | 필드 | 설명 |
|---|---|---|---|
| 0 | u8×4 | magic | `"OWLS"` |
| 4 | u8 | version | `1` |
| 5 | u8 | type | `1` 오디오, `2` 이벤트 로그 |
| 6 | u8 | codec | `0` PCM16, `1` Opus (type=2면 `0`) |
| 7 | u8 | frame_ms | Opus 프레임 길이 (보통 20) |
| 8 | u32 | id | 세그먼트 번호 (단조 증가, 재부팅해도 이어짐) |
| 12 | u32 | boot_count | 녹음 시작 시점의 부팅 번호 |
| 16 | u64 | start_uptime_ms | 해당 부팅 기준 시작 시각 |
| 24 | u16 | sample_rate_div100 | 16000Hz → `160` |
| 26 | u8 | channels | `1` |
| 27 | u8 | reserved | `0` |
| 28 | u32 | payload_len | 헤더 뒤 바이트 수 |

### 3.2 오디오 payload (type=1)

```
반복: [len u16][Opus 패킷 len 바이트]
```

프레임 수 × frame_ms = 녹음 길이. VAD로 끊긴 구간은 세그먼트를 새로 시작해요(무음은 저장하지 않음).

### 3.3 이벤트 payload (type=2)

```
반복: [uptime_ms u64][event u8][arg u8]
```

| event | 의미 | arg |
|---|---|---|
| `1` | 북마크 (버튼 짧게) | 0 |
| `2` | 녹음 꺼짐 | 원인: `0` 버튼(2초), `1` 앱 |
| `3` | 녹음 켜짐 | 원인: `0` 버튼(2초), `1` 앱 |
| `4` | 저장 공간 가득 참 (녹음 멈춤) | 0 |
| `5` | 배터리 부족 (3.6V 아래) | 0 |
| `6` | 기기 꺼짐 | 원인: `0` 버튼(5초), `2` 배터리(3.5V 아래) |
| `7` | 기기 켜짐 | 원인: `0` 버튼(5초), `3` 충전 확인 후 자동, `4` 그 밖의 재시작 |

이벤트는 생길 때마다 바로 플래시에 써요(`decisions.md` #19). 상태를 바꾸는 이벤트(2, 3, 6, 7)는 바뀐 **결과**를 적어서, 중간 이벤트가 빠져도 폰이 상태를 잘못 이어 붙이지 않아요.

## 4. 시간 처리

기기에는 RTC 배터리가 없고, 재부팅하면 uptime이 0부터 다시 시작해요. 그래서:

1. 기기는 부팅할 때마다 `boot_count`를 1 올려 플래시에 저장해요.
2. 모든 기록은 `(boot_count, uptime_ms)`로만 남겨요.
3. 폰은 연결할 때마다 TIME_SYNC를 보내고, 응답으로 받은 `(boot_count, uptime_ms)`와 자기 시각을 짝지어 저장해요.
4. 세그먼트의 실제 시각 = 같은 `boot_count`의 sync 기록에서 역산.

같은 부팅 안에서 한 번이라도 sync가 있으면 그 부팅의 모든 기록 시각을 복원할 수 있어요.
sync 없이 재부팅된 부팅 구간은 시각을 "알 수 없음"으로 표시해요(앞뒤 sync로 대략 추정은 가능).

## 5. 동기화 흐름

폰이 시작해요. 기기가 근처에 있는 동안 **15분마다** 아래 흐름을 돌리고, 앱의 "지금 동기화"와 앱을 켤 때도 바로 시작해요.
연결이나 요청이 실패하면 앱이 정한 횟수만큼 다시 시도하고, 그래도 실패하면 앱은 기기를 "연결 끊김"으로 표시해요(`decisions.md` #15, #16).

```
폰                                   기기
 │── connect, MTU 247, 2M PHY ───────▶│
 │── subscribe STATUS/CONTROL/DATA ──▶│
 │── TIME_SYNC ──────────────────────▶│
 │◀───────────── boot_count, uptime ──│
 │── LIST_SEGMENTS(after=0) ─────────▶│
 │◀──────────── [{id,type,size}, ...] │
 │── FETCH_SEGMENT(id, 0) ───────────▶│
 │◀──────── DATA chunk × N ───────────│
 │   (CRC32 계산, 로컬 저장)          │
 │── ACK_SEGMENT(id, crc) ───────────▶│  → 기기: 삭제 가능 표시
 │   ... 다음 세그먼트 반복 ...       │
 │── disconnect ─────────────────────▶│
```

폰은 받은 세그먼트를 **디스크에 먼저 저장한 뒤** ACK해요. 순서가 바뀌면 앱이 죽었을 때 데이터가 사라져요.

## 6. 저장 용량과 동기화 주기

| 항목 | 값 |
|---|---|
| Opus 16kHz 모노 16kbps | 2 KB/s = 약 7.2 MB/h |
| 플래시 16MB 중 오디오 영역 (약 15MB 가정) | **약 2시간 분량의 음성** |
| 12kbps로 낮추면 | 약 2.8시간 |

VAD로 무음을 빼도 대화가 많은 날은 하루 음성이 이보다 길어요. 그래서 **폰이 근처에 있으면 15분마다 동기화**해요(5장).
폰 없이 2시간 넘게 말하면 플래시가 차요. 그러면 새 녹음을 멈추고(STATUS bit3, 이벤트 4) 폰이 가져가 공간이 생기면 다시 녹음해요. 오래된 것을 덮어쓰지 않아요(`decisions.md` #17).

## 7. 버전 관리

- 호환이 깨지는 변경 → STATUS `proto_ver`와 세그먼트 `version`을 올려요.
- 필드 추가는 reserved를 먼저 쓰고, 부족하면 끝에 붙여요(길이로 구분).
