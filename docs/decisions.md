# 설계 결정 기록

새 결정은 아래에 번호를 이어 붙여요. 뒤집을 때는 지우지 말고 "대체됨: #N"을 적어요.

## 결정됨

1. **모노레포** — 펌웨어·앱·도구가 BLE 프로토콜을 공유하므로 한 커밋에서 같이 바뀌어야 함
2. **STT는 폰에서** — nRF54L15로 온디바이스 STT 불가. 기기는 Opus로 압축 저장만
3. **배치 전송, 실시간 스트리밍 없음** — 무선 시간 최소화로 배터리 절약
4. **GPS 없음, 폰 위치 사용** — CDM + PendingIntent 위치 기록
5. **풀(pull) 방식 프로토콜 + ACK 후 삭제** — 끊겨도 유실 없음, 이어받기 쉬움
6. **기기는 (boot_count, uptime)만 기록, 시각 변환은 폰** — RTC 배터리 없음
7. **배터리 250mAh (TW502030)** — 보드 충전 전류 200mA 고정이라 1C ≥ 200mA 필요. 100mAh(2C), 200mAh DTP452030(최대 0.5C)은 탈락
8. **방전 차단 3.5V** — 3.3V 아래에서 보드 소비 전류가 약 3µA → 약 450µA로 뛴다는 사용자 실측이 있음([Seeed 포럼](https://forum.seeedstudio.com/t/xiao-nrf54l15-with-a-coin-battery/294019?page=2), [포럼 2](https://forum.seeedstudio.com/t/xiao-nrf54l15-wrong-design-for-low-power/295257)). 원인(벅 컨버터 TPS62843의 100% 모드 추정)은 미확인. 3.5V는 그 위로 둔 여유값이고 M5에서 실측으로 확인
9. **배포 빌드는 UART 끔** — 위키: UART 켜면 배터리 단독 부팅 실패 가능(하드웨어 v1.0 기준). 회로도 V1.2에 "UART 역류 방지 U12 추가"가 있어 V1.2 보드에선 해결됐을 수 있음 → M0에서 보드 버전 확인
10. **STT는 폰 온디바이스만, 클라우드 없음** — 음성·위치·텍스트가 기기와 폰 밖으로 나가지 않게(PRD N8). 앱 설정에 변환 위치 선택지 없음 (PRD 10장 B 해소)
11. **음성 보관: 사용자가 기간 선택(기본 30일) + 기록별 "음성 보존"** — 선택지 7일 / 30일 / 90일 / 지우지 않음 / 추출 후 바로 삭제. 텍스트는 지우지 않음 (PRD 10장 F 해소, A14)
12. **녹음 파라미터(비트레이트·VAD 민감도·세그먼트 길이)는 앱에 노출하지 않음** — `SET_CONFIG`는 프로토콜에 남기되 개발용(`tools/`)으로만 사용
13. **버튼: 짧게 = 북마크, 2초 = 녹음 끄기/켜기, 5초 = 기기 끄기/켜기** — 녹음 끄기는 타인 대화 녹음 위험(PRD 11장) 때문에 폰 없이 바로 할 수 있어야 함. 앱에서도 녹음을 끄고 켤 수 있음(`SET_RECORDING`). 기기 끄기는 진짜 꺼짐(System OFF, 광고도 꺼짐) (PRD 10장 E 해소)
14. **녹음 꺼짐 상태는 저장해서 유지** — 기기가 꺼졌다 켜져도(버튼, 배터리, 재시작) 녹음은 꺼진 채로 시작. 모르는 사이 녹음이 다시 켜지는 걸 막음
15. **동기화는 폰이 15분마다 시작** — 기기는 켜져 있는 동안 1초 간격으로 늘 광고(배터리 1% 미만 추정). 기기가 부르는 방식(평소 광고 끔)은 앱의 "지금 동기화"가 바로 안 되고 지연이 불규칙해서 탈락. 항상 연결은 구현이 가장 어려워서 탈락
16. **연결 끊김 판정: 재시도까지 실패하면 바로** — 앱을 켤 때마다 다시 연결을 시도하고, 기기 화면에 연결 버튼을 둠. 꺼진 기기와 멀리 있는 기기는 폰이 구분할 수 없어서 둘 다 "연결 끊김" (PRD 10장 G 해소)
17. **플래시가 가득 차면 녹음 중단 + LED + 이벤트** — 덮어쓰지 않음(PRD D4). 폰이 가져가 공간이 생기면 다시 녹음 (PRD 10장 A 해소)
18. **플래시는 LittleFS** — 세그먼트 = 파일, ACK 후 삭제. `boot_count`·다음 세그먼트 id·녹음 꺼짐 상태도 같은 파일시스템에. 닳음 분산과 전원 차단 복구를 직접 짜지 않으려고. 원형 버퍼를 직접 짜는 방식은 오버헤드가 없지만 복구 코드 부담으로 탈락
19. **이벤트는 생길 때마다 바로 플래시에 기록** — 갑자기 꺼져도 북마크를 잃지 않게(PRD N4). 하루 수십 개라 용량·수명 부담 없음
20. **배터리: 3.6V 경고, 3.5V System OFF, 배터리로 꺼졌을 때만 1시간마다 깨어나 확인** — 보드에 USB 꽂힘 감지 핀이 없어서(회로도 V1.2) 충전기를 꽂아도 칩이 모름. 그래서 GRTC 타이머로 1시간마다 깨어나 3.8V 이상이면 켜짐. 버튼으로 끈 경우엔 타이머를 걸지 않음
21. **LED(초록 1개) 패턴** — 평소엔 꺼둠. 추정 소비는 켜질 때 약 0.9mA라 아래 깜빡임은 평균 0.01mA 이하

    | 상황 | 패턴 |
    |---|---|
    | 녹음 켜져 있는 동안 | 10초마다 1번 짧게 |
    | 북마크 | 1번 아주 짧게 |
    | 버튼 누르는 중 2초 / 5초 도달 | 1번 깜빡 / 3번 빠르게 (지금 놓으면 무엇이 되는지) |
    | 녹음 켜짐 / 꺼짐 | 1번 길게 / 2번 짧게 |
    | 기기 켜짐 / 꺼짐 | 3번 길게 / 1번 길게 후 꺼짐 |
    | 배터리 부족 (3.6V 아래) | 30초마다 3번 짧게 |
    | 저장 공간 가득 | 30초마다 2번 길게 |

22. **앱 자동 백업·기기 간 이전 끔** — `android:allowBackup="false"` + `dataExtractionRules`로 클라우드 백업·기기 이전 모두 제외. Android 기본값이면 녹음·DB가 Google Drive로 올라가서 PRD N8 위반. 폰을 바꿀 때 기록 이동은 내보내기(A13)로
23. **M1에서는 녹음을 PC에서 재생하지 않음** — PC로 꺼낼 길(BLE, `tools/sync.py`)이 M3에서 생김. M1은 시리얼 로그로 저장 확인까지
24. **프로토콜 레퍼런스 이름 `owlproto.py`, 세그먼트 magic `"OWLS"`** — 예전 이름(lifelog pendant) 흔적 정리. 아직 아무 데도 구현되지 않아 비용 없음
25. **nRF Connect SDK v3.4.1로 고정** — CI(`firmware.yml`)와 로컬 Docker 빌드가 같은 Nordic 공식 toolchain 컨테이너를 써요. 올릴 때는 `firmware.yml`의 `NCS_VERSION`과 `image:` 태그를 같이
26. **libopus 1.5.2를 CMake `FetchContent`로 받아 고정소수점(fixed-point) 빌드** — SHA-256 고정. west 모듈로 넣으면 워크스페이스가 `west init -m sdk-nrf` 하나로 끝나지 않고, 레포에 넣으면 8MB 외부 코드가 섞여서 탈락. 인코더 complexity 3은 추정값이라 M2 보드에서 프레임당 인코딩 시간을 보고 조정
27. **플래시의 세그먼트 헤더 `payload_len`은 `0xFFFFFFFF`, 보낼 때 채움** — LittleFS는 파일 앞을 고치면 뒤 블록을 다시 써서 세그먼트마다 두 번 쓰게 됨. 전송 바이트는 그대로 (프로토콜 3장)
28. **프로토콜 v1 세부 규칙 11가지 확정** — LIST는 빈 응답이 끝, FETCH는 대체, 끝 표시 없음, 이벤트 로그는 연결 시 닫음 등. PC 도구 구현 중 발견해 펌웨어·앱이 같은 규칙으로 구현함 (프로토콜 5.1장)
29. **M0 bring-up은 별도 앱 `firmware/bringup/`** — 본 앱이 모듈로 나뉜 뒤에도 보드 도착 직후 부품 확인을 따로 돌릴 수 있게. 외장 플래시 마지막 4KiB 섹터를 쓰고, 본 앱의 LittleFS 파티션은 그 섹터를 비워둠
30. **타임라인 기록 하나 = 간격 2분 이하로 이어진 세그먼트 묶음** — 세그먼트는 최대 5분(SET_CONFIG key 3)이라 하나씩 보여주면 대화가 잘게 잘림. 부팅이 다르거나 시각을 모르는 세그먼트, 녹음 꺼짐 이벤트를 사이에 둔 세그먼트는 합치지 않음. 기준값은 앱 상수 `ENTRY_MERGE_GAP_MS`. 기록 단위 메뉴(음성 보존·삭제·복사)는 묶음 전체에 적용 (PRD A7)
31. **녹음이 없을 때 누른 북마크는 타임라인에 단독 항목으로 표시** — 버리면 사용자가 남긴 표시가 사라짐 (PRD A9)
32. **장소 이름은 사용자가 붙임** — 네트워크 지오코딩은 위치가 폰 밖으로 나가서(PRD N8) 쓰지 않고, 오프라인 지명 데이터는 앱 용량이 수십 MB 늘어서 탈락. 이름이 없으면 "알 수 없는 장소", 기록 상세에서 이름을 붙이면 반경 100m(앱 상수 `PLACE_RADIUS_M`, 실제 폰 GPS 오차로 다시 확인) 안의 지난·앞으로의 기록에 자동 적용 (PRD A5)
33. **BLE 보안: LE Secure Connections 본딩, 새 페어링은 등록할 때만** — 보안이 없으면 근처의 누구나 녹음을 내려받고 ACK로 지울 수 있음(PRD N8). CONTROL·DATA는 암호화된 연결에서만 허용. 새 페어링은 본딩된 폰이 없을 때나 기기를 켠 직후 짧은 시간(약 2분)에만 받음. 기기에 화면·키패드가 없어 Just Works 방식이라 페어링 순간의 중간자 공격은 막지 못하지만, 그 창이 짧음. 구현은 프로토콜·펌웨어·앱·`tools/`를 한 커밋에서 (PRD A1, N8)
34. **페어링 창은 켠 뒤 120초, 그 안에서 새 본딩 하나** — 본딩된 폰이 있으면 새 페어링은 BLE가 켜진 뒤 120초(`PAIRING_WINDOW_MS`) 안에서만, 그리고 그 창에서 새 본딩이 하나 생기면 닫혀요. 2분은 껐다 켜고 앱에서 등록하기에 넉넉하고, 하나만 받는 건 등록 직후 옆 사람이 바꿔치기하지 못하게예요. 본딩이 없으면 언제나 받아요 (프로토콜 2.4장)
35. **본딩은 폰 하나, 새 본딩이 완료되면 이전 것을 지움** — 폰을 잃어버려도 껐다 켜고 2분 안에 새 폰을 등록하면 돼요. 이전 본딩은 새 페어링이 *성공한 뒤에* 지워서, 실패하면 원래 폰이 그대로 남아요(펌웨어는 그동안 쓸 자리로 `CONFIG_BT_MAX_PAIRED=2`). 같은 폰의 재페어링도 창 안에서는 받아요(`CONFIG_BT_SMP_ALLOW_UNAUTH_OVERWRITE`; 주소를 흉내 내도 창 밖에선 `pairing_accept`가 거절). PC(`tools/sync.py pair`)도 같은 규칙이라, PC를 페어링하면 폰은 다시 등록해야 해요
36. **STATUS 값만 암호화 없이 읽기 허용, STATUS bit4 = 페어링 열림** — STATUS엔 녹음 내용이 없고 아무것도 바꾸지 못해요. 등록 전에 "지금 페어링되는지" 알 수 있어 안내가 쉬워져요. 대가는 근처 사람이 미전송 개수 같은 활동량 힌트를 볼 수 있다는 것. 구독(CCCD)은 셋 다 암호화 필요. 와이어 포맷은 그대로라 프로토콜 v1 유지
37. **본딩 지우기는 CONTROL `UNPAIR`(op 7)로, 버튼 동작은 추가 안 함** — 앱의 "등록 해제"가 UNPAIR를 보내 기기가 모든 본딩을 지우고, 이후엔 아무 폰과도 페어링돼요. 폰을 잃어버린 경우는 껐다 켜기(#34)로 충분해서, 버튼 동작(짧게·2초·5초, PRD D7·D8·D8a)을 늘리지 않았어요
38. **본딩된 폰엔 기기가 먼저 Security Request, 60초 안에 암호화 안 되면 끊기** — Android 12–15는 연결만으로는 암호화하지 않아서(AOSP 확인) 기기가 요청해요. 모르는 상대에겐 보내지 않아요(페어링 창이 아무 폰에나 뜨지 않게). 기기는 한 번에 하나만 연결되니 암호화 안 된 연결이 그 자리를 붙잡지 못하게 60초(`UNENCRYPTED_TIMEOUT_MS`) 뒤 HCI 0x05로 끊어요
39. **본딩 키는 칩 안 RRAM `storage_partition`에 (Zephyr settings + ZMS)** — NCS v3.4.1의 nRF54L15 기본 배치(`0x174000`, 36KiB)라 따로 파티션을 만들지 않아도 되고, 외장 플래시의 LittleFS·bring-up 섹터(#29)를 건드리지 않아요. `FILE_SYSTEM=y`라 settings 기본 저장소가 LittleFS 파일이 되므로 `CONFIG_SETTINGS_ZMS`를 직접 지정
40. **앱: 등록할 때 `createBond()`, 실패하면 등록 취소. 폰에 본딩이 없으면 연결하지 않음** — CDM 등록 직후(10분 안) 앱이 부른 `createBond()`는 Android 설정 앱이 확인 창 없이 받아요(AOSP `BluetoothPairingRequest`). 거절되면 CDM 등록도 되돌려 반쯤 등록된 상태를 남기지 않아요. 백그라운드 동기화 중 페어링 창이 뜨지 않게, 본딩이 없으면 연결 전에 "다시 등록 필요"로 멈추고 재시도하지 않아요. 등록 해제는 UNPAIR → 폰 본딩 삭제(API 36은 `CompanionDeviceManager.removeBond`, 그 아래는 `BluetoothDevice.removeBond` 리플렉션: `@SystemApi`지만 hidden API 차단 목록에 없음) → CDM 해제
41. **에뮬레이터에서 앱의 진짜 BLE 경로는 Bumble 가짜 목걸이로 시험** — Android 에뮬레이터의 블루투스는 가상 컨트롤러(netsim)라 Google Bumble이 같은 가상 라디오에 BLE 기기로 붙을 수 있어요(`android-netsim` 전송). 그래서 `tools/fake_owl.py --transport bumble`이 기존 기기 모델(`owlsync/device.py`)을 그대로 광고하고, 앱은 코드 수정·debug 우회 없이 CDM 등록·`createBond()`·암호화·동기화·UNPAIR를 진짜 경로로 지나가요(2026-11-01 API 37에서 확인, `android/README.md`). `bless`(macOS)는 페어링을 거절할 수 없고 이 Mac에서 블루투스 권한도 못 받아 탈락. netsim은 키 분실을 0x06 대신 0x05로 흉내 내서 그 경우만은 하드웨어에서 확인해야 해요
42. **Bumble 가짜 목걸이는 SMP·ATT 결과를 펌웨어(Zephyr)와 같게** — 본딩 안 하는 요청 0x08, LE legacy 0x03, 창 닫힘 0x08(Zephyr `smp_pairing_req()`·`smp_err_get()` 소스 확인), 본딩 없는 상대 ATT 0x05·본딩은 있는데 암호화 전 0x0F. 같은 규칙을 Bumble 가상 링크 두 개로 진짜 SMP를 돌리는 `tools/tests/test_bumble.py`가 CI에서 확인해요(그래서 `bumble`을 `tools/requirements.txt`에 고정). 에뮬레이터 E2E는 에뮬레이터가 있어야 해서 CI에선 안 돌려요
43. **앱 테마는 설정에서 고름(다크 / 라이트 / 시스템 설정 따름), 기본은 다크** — 사용자가 고른 기본값. 값은 DataStore(`theme_mode`)에 두고, 같은 값을 `UiModeManager.setApplicationNightMode`(API 31+, 앱별로 Android가 저장)에도 넘겨요. 그래서 Compose가 그리기 전 시작 창(`res/values-night`)도 다음 실행부터 고른 테마예요. XML 테마를 항상 다크로 두는 방법은 라이트를 고른 사람이 켤 때마다 어두운 창을 보게 돼서 탈락. 대가: 설치 후 **첫 실행**만은 앱 코드가 돌기 전이라 시작 창이 폰 테마를 따라요(라이트 폰이면 잠깐 밝음). 테마를 바꾸면 Android가 화면(Activity)을 한 번 다시 만들어요(보던 화면은 그대로) (PRD A17). 확인(2026-11-01, 에뮬레이터 API 37, debug): 밝은 건 시스템 시작 창뿐이고 Compose 화면은 첫 프레임부터 다크(첫 실행 시작 창은 2.7–3.7초, 첫 콜드 스타트라 김). 앱별 night mode는 업데이트 설치(`installDebug`)에선 남고, 앱 삭제·데이터 삭제(`pm clear`)에선 지워져서 그 뒤 첫 실행이 설치 직후와 같아요(AOSP `PackageConfigPersister`의 `onPackageUninstall`·`onPackageDataCleared`). 런처 시작 창을 늘 다크로 하는 길은 없어요: "아직 안 정함"과 "라이트"가 둘 다 `notnight` 리소스로 보여서 구분 못 함
44. **목걸이가 우리 키를 거절하면(2.4장 흐름 5) API 36+는 암호화 브로드캐스트로 알아냄** — Android 16+는 저장된 키로 한 암호화가 실패하면 폰이 스스로 연결을 끊어서(AOSP `btm_sec.cc`, 플래그 `disconnect_on_encryption_failure`) 앱은 HCI 0x16(로컬 호스트가 끊음)만 받아요. 0x16은 다른 이유로도 오니 그것만으로 "다시 등록"을 띄우진 않고, API 36에 공개된 `ACTION_ENCRYPTION_CHANGE`(실패 status 0x05·0x06·0x25, AOSP가 LE 키를 잊는 조건과 같음)나 `ACTION_KEY_MISSING`이 같은 기기에 대해 오면 `NotBondedException`으로 바꿔요. 두 경로가 달라 브로드캐스트가 끊김 콜백보다 늦게 올 수 있어서(에뮬레이터에서 약 9ms 뒤) 0x16이면 최대 1초 기다려요. API 31–35는 끊지 않고 GATT 작업이 137로 끝나 기존 처리로 충분해요(소스 확인, 기기 미확인). 둘 다 보호된 브로드캐스트라 다른 앱이 흉내 낼 수 없어요. 에뮬레이터(API 37)에서 "다시 등록 필요"까지 확인, 진짜 컨트롤러의 0x06은 하드웨어에서 확인해야 해요
45. **앱 QA는 Bumble 가짜 목걸이에 일주일 치 데이터를 부팅별로 재생해서** — 폰은 그 부팅 안에서 받은 TIME_SYNC로만 시각을 복원해요(프로토콜 4장).
    QA 폰은 "지금"에만 있어서, 가짜 목걸이(`tools/owlsync/week.py`)가 지난 부팅을 지금 uptime(= 지금 − 켜진 시각)으로 하나씩 보여주고
    동기화가 끝날 때마다 다음 부팅으로 넘어가요. 폰에 쌓이는 시각은 15분마다 동기화했을 때와 같아요. 에뮬레이터 시계를 과거로 돌리는 방법은
    Play 이미지에 root가 없어 탈락. 지난 날의 폰 GPS와 텍스트는 debug 빌드에만 있는 명령(`import-locations`, `demo-stt`)으로 넣어요
    (`geo fix`는 지금 시각만, 진짜 목걸이 등록이면 STT가 없음). 시나리오와 결과는 `docs/qa/` (2026-11-01)
