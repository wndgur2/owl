# QA 시나리오 — Android 앱 × Bumble 가짜 목걸이 (진짜 BLE 경로)

| 항목 | 내용 |
|---|---|
| 범위 | Android 앱(debug 빌드)을 에뮬레이터에서, `tools/fake_owl.py --transport bumble --week`(가짜 목걸이, `decisions.md` #41·#42)에 진짜 BLE로 붙여서 시험. 앱 안의 `FakeOwlDevice`·PC `sync.py`는 범위 밖 |
| 기준 | [PRD](../prd.md) D1–D12(앱에서 보이는 부분)·A1–A17·N4·N8, [프로토콜](../../protocol/ble-protocol.md) 2.4장·4장·5.1장, [설계 결정](../decisions.md) |
| 데이터 | 일주일 치 시드 (아래 "준비") |
| 결과 | [2026-11 QA 보고서](2026-11-qa-report.md) |

기기 쪽 동작(D1 VAD, D3 Opus 인코딩, D9 LED, D10 전압 차단, D11 충전, D12 펌웨어 업데이트)은 하드웨어가 있어야 해서 여기서는
**앱에 보이는 결과**(이벤트·STATUS가 앱에 어떻게 나타나는지)만 봐요.
텍스트는 debug 빌드의 `DemoTranscriber` 고정 문장이에요(진짜 STT는 M6). 문장 내용이 녹음과 안 맞는 건 버그가 아니에요.

## 준비

### 에뮬레이터와 앱

- AVD는 API 37 이미지(`Medium_Phone`과 같은 `google_apis_playstore_ps16k`). 다른 세션이 `emulator-5554`를 쓰고 있을 수 있으면 따로 띄워요
  (이번 QA는 `Owl_QA`, `emulator-5556`). 에뮬레이터들은 netsim 하나를 같이 써서 Bumble 가짜 목걸이는 모든 에뮬레이터에 보여요.
  다른 에뮬레이터 앱이 등록한 이름(`Owl-FA4E`)과 겹치지 않게 가짜 목걸이 이름을 바꿔요(`--name Owl-0A7E`).
- 앱: `cd android && ./gradlew installDebug` (깨끗하게 시작하려면 먼저 `adb uninstall dev.owl.app`).

### 일주일 시드 (`tools/owlsync/week.py`)

```bash
cd tools
rm -f /tmp/qa.json /tmp/qa.keys.json            # 새 목걸이처럼 (부팅 1, id 1부터)
python fake_owl.py --transport bumble --name Owl-0A7E --state /tmp/qa.json --week --locations-out /tmp/qa_fixes.csv \
    --phone-clock-offset -9.4                   # 에뮬레이터 시계 − 이 컴퓨터 시계(초). 재는 법은 tools/README.md
```

에뮬레이터 시계는 컴퓨터와 몇 초 다를 수 있어요(이번 QA: −9.4초). 이걸 안 주면 14:00:00 녹음이 앱에서 13:59로 보여요(앱 버그 아님).

시드는 오늘 날짜를 기준으로 7일 전 아침부터 지금(20분 전)까지를 만들어요. 같은 날짜·`--seed`·state면 늘 같은 데이터예요.

| 날 | 부팅 | 내용 (시나리오에서 쓰는 것) |
|---|---|---|
| D-7 | 부팅 1 켜짐 09:00 (버튼) | 집 09:30, 카페 13:20, 집 20:10 대화. 7일 보관 기간에 걸리는 가장 오래된 음성 |
| D-6 | | 공학관 수업. 10:28:00·10:29:30 녹음 사이에 녹음 꺼짐(버튼)·켜짐 → **간격 87초여도 안 묶임**. 10:31 녹음 꺼짐 → 11:10 북마크(**단독**) → 11:45 켜짐. 학생회관 12:31 북마크(대화 안), 도서관, 집 |
| D-5 | | 실험실, 공학관 14:00:00(3초)·14:02:03(3초)·14:04:07 → **120초 간격은 묶이고 121초는 안 묶임**, 14:01 북마크는 묶인 항목 사이 간격에 있어서 그 항목에 붙음. 21:30 배터리 부족, 22:40 배터리로 꺼짐 |
| D-4 | 부팅 2 켜짐 07:50 (충전 후 자동) | 13:00–16:00 **위치 기록 없음**(14:00 도서관 대화는 장소 없음), 14:05 북마크. 18:00 **앱에서** 녹음 꺼짐 → 18:40 단독 북마크 → 19:30 켜짐 |
| D-3 | 18:00 버튼으로 끔. **부팅 3 켜짐 20:00, 동기화 한 번도 없이** 21:05 재시작(부팅 4) | 부팅 3: 20:10·20:40 대화, 20:12 북마크(대화 안), 20:55 북마크(대화 밖) → **시각 알 수 없음** |
| D-2 | | 공학관·학생회관·도서관(14:50 북마크)·카페. 16:20 단독 북마크 |
| D-1 | | 10:35 **집에서 85m 떨어진 편의점** 대화(집 이름을 붙이면 같이 "집", 반경 100m). 카페 13:30 대화, 16:40 저장 공간 가득 참, 22:10 배터리 부족 |
| D0 | 부팅 4 (지금) | 집 10:00(10:05 북마크), 카페 14:00, 집 17:30 (지금보다 20분 이상 전인 것만). 오늘 이벤트는 열린 이벤트 로그(연결할 때 닫힘) |

규모: 대화 하나 = 50–110초 간격의 2–3초 세그먼트들. 시각은 실제처럼, **오디오는 짧게** 줄였어요(30분 대화 ≈ 세그먼트 20개 ≈ 1분 오디오).
전체 약 530개 세그먼트, 약 2MB(Opus 16kbps). 세그먼트마다 문장 1개(`DemoTranscriber`는 9초에 1문장, 최소 1).

**부팅을 하나씩 보여주기** — 폰은 그 부팅 안에서 받은 TIME_SYNC로만 실제 시각을 복원해요(프로토콜 4장). 실제로는 폰이 일주일 동안 15분마다
동기화했겠지만 여기선 폰이 "지금"에만 있어서, 가짜 목걸이가 부팅을 하나씩 보여줘요: 부팅 1을 그 부팅의 지금 uptime(= 지금 − 켜진 시각)으로
보여주고, 그 부팅에서 TIME_SYNC가 있었던 연결이 끊기면 다음 부팅으로 넘어가요. 그래서 **동기화를 세 번** 하면 일주일이 다 들어와요
(부팅 1 → 2 → 4. 부팅 3은 건너뛰어서 시각을 모르는 채로 부팅 4와 같이 넘어감). 폰이 받는 시각은 실제로 15분마다 동기화했을 때와 같아요.
다른 점은 "받은 시각"이 모두 지금이라는 것뿐이에요(보관 기간은 녹음 시각 기준이라 영향 없음).

**장소** — 앱은 녹음 가운데 시각에서 15분 안의 가장 가까운 폰 GPS를 써요(`PlaceResolver`). 에뮬레이터 `geo fix`는 "지금" 시각으로만 찍혀서
지난 날의 위치는 debug 전용 명령으로 넣어요(5분 간격, 15m 흔들림, 정확도 20–60m):

```bash
adb push /tmp/qa_fixes.csv /data/local/tmp/ && adb shell run-as dev.owl.app cp /data/local/tmp/qa_fixes.csv files/qa_locations.csv
adb shell am broadcast -a dev.owl.app.debug.FAKE -p dev.owl.app --es cmd import-locations
```

지금 녹음하는 것(QA 중 `record`)의 위치는 진짜 경로(`adb emu geo fix <경도> <위도>` → FusedLocationProvider → `LocationReceiver`)로 확인해요.
에뮬레이터 주의: 앱은 절전 정확도(BALANCED, Wi-Fi·기지국 위치)로 요청해서, 에뮬레이터에선 다른 앱이 GPS를 켜고 있어야 위치가 와요
(Google 지도를 띄워 두면 됨. 플랫폼 테스트 위치 제공자 `cmd location providers`는 Play 서비스 FLP가 쓰지 않았어요).
또 `--name`을 다른 에뮬레이터에 등록된 이름과 다르게(이번 QA: `Owl-0A7F`) 해야 그 앱이 붙지 않아요.

**텍스트** — 진짜 목걸이로 등록하면 debug 빌드도 STT가 없어서 "텍스트 추출 중"으로 남아요(A8a 확인에 씀). 문장이 필요한 시나리오 전에
debug 전용 명령으로 고정 문장을 켜요: `--es cmd demo-stt --el arg 1`.

동기화 바로 시작: `adb shell am broadcast -a dev.owl.app.debug.FAKE -p dev.owl.app --es cmd sync` (로그 `adb logcat -s OwlSync OwlFake OwlBle`).
가짜 목걸이 표준 입력: `record`, `bookmark`, `rec`(버튼 2초), `battery MV`, `storage KB`, `reboot`, `drop N`, `lose N`, `status`, `next`.
